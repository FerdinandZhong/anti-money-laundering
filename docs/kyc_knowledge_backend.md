# Step 2: local KYC evidence backend

For the connected scanned-document/control/audit demonstration, use [the current prototype guide](kyc_audit_and_multimodal_demo.md). The standalone Markdown and nine-PDF ingestion modes below remain available.

The workbench Documents tab now reads an immutable LanceDB release, searches English/Chinese evidence, and opens the original document at the cited page. The existing Markdown dossiers remain the fallback when no knowledge release is available. This is evidence retrieval, not a regulatory compliance decision engine (Step 3).

## Prepare a release

From the project root, install the main project requirements, then run:

```bash
python 02_backend/scripts/prepare_kyc_knowledge.py
```

This imports `data/kyc_documents/*/*.md` and builds keyword search. For standalone use, run after generating the demo data. AMP and registered CML jobs enable preparation within the existing generation job by default; no separate job is required. Markdown receipt times use file modification times, so newly generated files can be later than an existing alert cutoff.

To include the nine bilingual PDF extraction samples previously generated by `kyc_extraction_poc.py`:

```bash
python 02_backend/scripts/prepare_kyc_knowledge.py --include-poc
```

To connect the Step 3 demo controls to indexed, versioned source records, add `--include-control-demo`. The five synthetic Markdown records become scoped LanceDB documents. The evaluator parses their indexed page text and cites the release, version, chunk and page. A release without these records leaves controls without mapped evidence; missing LanceDB returns an explicit unavailable result.

These samples are explicitly labeled illustrative and attached to showcase customer `CUST-000294`. Their fictional company identity is not a verified identity of that customer. Their September 1 receipt date is a demo assumption. Extraction errors remain visible in the retrieved evidence.

For semantic retrieval, install the optional runtime and supply a local BGE-M3 ONNX directory containing `model_quantized.onnx` and `tokenizer.json`:

```bash
python -m pip install -r 02_backend/scripts/requirements-kyc-embeddings.txt
export AML_EMBEDDING_MODEL_DIR=/absolute/path/to/bge-m3-onnx-int8
python 02_backend/scripts/prepare_kyc_knowledge.py --include-poc --embedding-model-dir "$AML_EMBEDDING_MODEL_DIR"
```

The tested model is [gpahal/bge-m3-onnx-int8](https://huggingface.co/gpahal/bge-m3-onnx-int8). The code makes no automatic model downloads. It uses normalized 1024-dimensional dense vectors, CPU inference, and a 512-token limit. Keep the model available to the running backend. Configure `knowledge.embedding_model_dir` or the environment variable when relocating it. A missing or mismatched model produces explicitly labeled keyword-only results.

## Data contract and storage

`--manifest path/to/documents.json` accepts an explicit JSON array. Asset paths are relative to that manifest; supply actual extraction output in `pages`, not generator answer keys:

```json
[
  {
    "document_id": "ownership-001",
    "customer_id": "CUST-000294",
    "account_id": "ACC-0000294",
    "title": "Ownership declaration",
    "path": "ownership.pdf",
    "received_at": "2026-09-01T00:00:00Z",
    "language": "mixed",
    "source": "Synthetic onboarding submission",
    "provenance": "Synthetic demo document",
    "pages": [{"page": 1, "text": "受益所有人 / beneficial owner: Chen Min", "evidence": []}]
  }
]
```

An omitted account means customer-wide evidence. Ingestion consumes extracted text and page evidence; it does not run OCR itself. Use the extraction script or another extractor upstream.

| Storage | Contents |
|---|---|
| `documents` Lance table | Document/version IDs, customer/account scope, receipt time, language, provenance, SHA-256, media type, immutable asset path |
| `chunks` Lance table | Same scope/version metadata, page, extracted text, OCR evidence JSON, lexical text, optional fixed-size vector |
| `releases/<id>/objects/` | Copied originals addressed by SHA-256 |
| `releases/<id>/manifest.json` | Counts, schema/tokenizer versions, embedding dimension and model/tokenizer hashes |
| `current.json` | Atomic pointer activated after the complete build |

Default storage is `data/knowledge/`, excluded from git. Override with `AML_KNOWLEDGE_DIR` or `knowledge.directory`. Identical inputs reuse a release; changes create a new release and retain previous citations. There is no automatic retention cleanup.

## API, workbench, and MCP

All paths below start with `/api/alerts/{alert_id}/knowledge`:

| Endpoint | Behavior |
|---|---|
| `GET /` (without trailing slash) | Scoped document library, release ID, alert cutoff |
| `GET /search?q=...&release=...&limit=10` | Cutoff-filtered keyword/vector retrieval with reciprocal rank fusion |
| `GET /assets/{version_id}?release=...` | Scoped original with SHA-256 verification |
| `GET /pages/{version_id}/{page}?release=...` | Scoped extracted text and page evidence |

Scope is derived server-side from the alert. Search excludes receipts after its cutoff; the browse library deliberately includes later receipts as context. The client pins its release for searches and original-document links. Authentication remains the application's existing deployment responsibility; these scope checks do not add a new identity/tenant authorization system.

MCP exposes `list_kyc_evidence(alert_id)` and `search_kyc_evidence(alert_id, query, release_id, limit)`. Automated investigation workers are not yet changed to consume these results. The UI displays provenance, fixture labels, snippets, and an original-document preview. OCR boxes are available through the API, but the viewer does not yet overlay them.

## Impala manual handoff

The existing publication script remains independent of LanceDB:

```bash
# Local typed CSV/Parquet round-trip and generated SQL only
python 02_backend/scripts/kyc_impala_publication_poc.py

# Run manually from your Impala-connected environment
python 02_backend/scripts/kyc_impala_publication_poc.py --execute
```

Outputs are under `artifacts/kyc_poc/publication/`. Remote mode creates a unique `aml_kyc_poc_*` test database, stages typed rows, publishes Iceberg tables, and checks exact readback and joins. It does not switch production datasets or drop the test database. Configure `source.impala` and the documented script environment overrides; credentials are read from `IMPALA_PASSWORD` or the local workload-password file. This tests SQL staging/publication, not external CSV upload. Remote execution is deferred to the user.

## Validation and remaining scope

The current local demo release contains two Markdown dossiers, nine extracted PDF fixtures, and five synthetic control source records (16 documents, 17 indexed chunks). Real LanceDB tests cover bilingual keyword search, customer/account isolation, temporal filtering, immutable releases, failed-build pointer preservation, original-document integrity, and API citations. Actual BGE-M3 hybrid searches and missing-model fallback are recorded in `artifacts/kyc_poc/knowledge/smoke_report.json`.

The larger audit corpus and wider regulatory control set remain pending. The first contextual mapping and conflicting-assertion slice is described in [the semantic control guide](kyc_semantic_controls.md). This small retrieval smoke check is not a retrieval-quality benchmark. Multi-page OCR layout quality, corpus-scale latency, and browser interaction still need broader evaluation.
